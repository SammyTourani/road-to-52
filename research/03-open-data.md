**Scope:** every stage — pretraining → code → math/science → midtraining/annealing/long-context → SFT → preference → RLVR → decontamination → disk planning.
**Verification method:** every row was checked live against the public Hugging Face API (`https://huggingface.co/api/datasets/{id}`), the repo's raw card (`/raw/main/README.md`), and/or the source paper. Repo byte sizes come from `https://huggingface.co/api/datasets/{id}/treesize/main`. Anything not confirmable from a primary source is marked **UNVERIFIED**.

> **Note on HF API behaviour:** HF returns **HTTP 401, not 404**, for a repo that does not exist. Every "does not exist" below was confirmed by org-level enumeration, not name-guessing.

> ### Two corrections to common assumptions
> 1. **There are no Claude-generated Magpie datasets.** A live enumeration of all 300 `Magpie-Align` repos found zero Claude variants — Magpie is Llama-3/3.1/3.3, Qwen2/2.5, Phi and Gemma based. The concern is unfounded.
> 2. **Dolphin is not Claude-derived either — it's Gemini-derived.** [`QuixiAI/dolphin-r1`](https://huggingface.co/datasets/QuixiAI/dolphin-r1) (org renamed from `cognitivecomputations`) is 800k samples = **300k DeepSeek-R1 + 300k Gemini 2.0 Flash Thinking + 200k Dolphin chat**. Different problem, same conclusion: avoid the Gemini split.

### 🚨 The one dataset you are most likely to ingest by accident

**[`SWE-bench/SWE-smith-trajectories`](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories)** — 76,002 rows, **tagged MIT**, widely recommended, and the headline SFT set behind SWE-agent-LM-32B's 40.2% on SWE-bench Verified.

Its own `model` column, read through the HF datasets-server statistics API, gives the exact split:

| generator | rows | share |
|---|---|---|
| `claude-3-7-sonnet-20250219` | 54,629 | 71.88% |
| `claude-3-5-sonnet-20241022` | 19,736 | 25.97% |
| `gpt-4o-2024-08-06` | 1,637 | 2.15% |
| **Claude total** | **74,365** | **97.85%** |

Corroborated by the card (*"generated by running SWE-agent + Claude 3.7 Sonnet"*) and [arXiv:2504.21798](https://arxiv.org/abs/2504.21798) (*"we generate 5,016 expert trajectories with Claude 3.7 Sonnet"*).

> The MIT tag does not help you: **a licence governs redistribution, the provider's ToS governs what you may train on.** Both apply, independently.

**⚠️ Even the SWE-smith *task* set is partially Claude-touched.** [`SWE-bench/SWE-smith`](https://huggingface.co/datasets/SWE-bench/SWE-smith) (59,136 tasks, MIT, no traces) includes an **`lm_rewrite`** subset whose *issue text* was LM-authored: the repo's [`issue_gen/generate.py`](https://github.com/SWE-bench/SWE-smith/blob/main/swesmith/issue_gen/generate.py) documents the invocation as `--model anthropic/claude-3-7-sonnet-20250219`. The template / F2P-log / PR-mirror strategies are unaffected. Exact per-strategy row split: **UNVERIFIED** — filter out `lm_rewrite` instances to be safe.

**It propagates.** [`QuixiAI/dolphin-distill`](https://huggingface.co/datasets/QuixiAI/dolphin-distill) folds in **142,585 SWE-smith-trajectories rows (1.23%)**. Audit transitively — §5.4b gives the one-call method.

**[`HuggingFaceCode/stack-v3-train`](https://huggingface.co/datasets/HuggingFaceCode/stack-v3-train)** — released under the **`HuggingFaceCode`** org (*not* `bigcode`), `lastModified` 2026-09-04, **209,076 downloads**, **`odc-by`**, **ungated**.

- **3.611T estimated tokens** · 2,267.5M files · 11.50 TB uncompressed · **713 languages** · 172,812,532 rows (1 row = 1 repo) · **3,546 GB Parquet on HF**
- **Contents are inline** (`files[].content`, PII-redacted with [StarPII](https://huggingface.co/bigcode/starpii)). No Software Heritage, no S3 agreement, no egress bill. This alone makes it strictly better than v2 for most users.

- ⚠️ **Token count correction:** blogs citing "4.9T / 5T tokens" are quoting **v3.0**. A v3.1 patch fixed exact-dup leakage from a partitioning bug: **4.9T → 3.6T**. The repo's own `stats/train/stats_by_language.json` confirms 3.611T.
- **Scope caveat (card, verbatim):** *"This release focuses on source code and Jupyter notebooks. It does not include the additional non-code sources that accompanied StarCoder2 training (GitHub issues, pull requests, Kaggle notebooks, documentation, ArXiv, Wikipedia, OpenWebMath, etc.)"* → you still need `bigcode/starcoder2data-extras`.
- Also released: [`stack-v3-full`](https://huggingface.co/buckets/HuggingFaceCode/stack-v3-full) — **113.7 TB**, 224M repos, 770 langs, as an HF Storage Bucket. License breakdown of the full corpus is Apache-2.0-dominated (**7.73T tokens Apache-2.0** vs 880B CC-BY-4.0, 757B BSL-1.0, 520B CC0, 162B MIT).
- Opt-out: [`HuggingFaceCode/in-the-stack`](https://huggingface.co/spaces/HuggingFaceCode/in-the-stack), same [opt-out-v2](https://github.com/bigcode-project/opt-out-v2) flow. **No arXiv paper** (a HF-published `@misc{lozhkov2026stack-v3}`), which is why it's easy to miss.

### 2.3 Licensing pitfalls — concrete

1. **Where permissive-only-*with-content* actually exists:** (a) **`common-pile/stackv2`** — 218M docs, per-document SPDX, Blue Oak certified; (b) **The Stack v3** — excludes `non_permissive` by construction; (c) **`tokyotech-llm/swallow-code-v2`** (Apache-2.0); (d) **`openbmb/UltraData-Code`** (Apache-2.0). Nowhere else.
2. **Stack v1/v2 retained `no_license` files and did not exclude copyleft at the dataset level** — permissive detection was a *label*, not a filter. Stack v3 fixed this.
3. **NVIDIA's code corpora are metadata, not code.** SwallowCode-v2's card says it best: *"While datasets such as OpenCoder and NVIDIA/Nemotron-Pretraining-Code-v1 are labeled 'open,' they only release metadata… instead require large-scale re-crawling of GitHub repositories based on metadata. For smaller open-source LLM projects, this reconstruction process is prohibitively expensive."*
4. **Phi-4 license rider.** `Nemotron-CC-Code-v1` and `Nemotron-CC-Math-v1` were built with Phi-4; NVIDIA warns use *"may subject derivative AI models to the Phi-4 License Agreement requirements."* A real downstream-contamination vector.
5. **Permissive-only is best-effort, never a guarantee.** Common Pile states on every subset: *"license laundering and inaccurate metadata can cause us to erroneously assign the incorrect license to some documents."*
6. **Agent trajectories inherit repo licenses.** `nvidia/Open-SWE-Traces` restricted issue sources to **MIT / Apache-2.0 / BSD-2 / BSD-3** repos. Copy that practice.
7. **Non-commercial landmines:** `nvidia/Nemotron-ClimbMix` + `ClimbLab` (CC-BY-NC-4.0), `MegaScience/*` (CC-BY-NC-SA-4.0), `KodCode/KodCode-V1` (CC-BY-NC-4.0), `a-m-team/AM-DeepSeek-R1-Distilled-1.4M` (CC-BY-NC-4.0), `Salesforce/APIGen-MT-5k` (CC-BY-NC-4.0).
8. **Viral ShareAlike:** `math-ai/AutoMathText` (CC-BY-SA-4.0), `BAAI/Infinity-Instruct` (CC-BY-SA-4.0), parts of `nvidia/Nemotron-Math-v2` and `Nemotron-SFT-Math-v4` (CC-BY-SA-4.0 for the Math-StackExchange-derived rows).

> 🚩 **Action item:** Dolmino contains a **"Gemini Reasoning Traces"** source. Claude-free ✅ but **Gemini-derived ⚠️**. Ai2 ships it ODC-By; a commercially-cautious project should filter it out on the parquet `source` field. (Ai2 does not publish per-source row IDs, so you filter at read time.)

### 4.2 SmolLM3 (Hugging Face) — 11.2T tokens, 3 stages

[HF blog](https://huggingface.co/blog/smollm3) · [The Smol Training Playbook](https://huggingfacetb-smol-training-playbook.hf.space) · configs: [huggingface/smollm](https://github.com/huggingface/smollm), [HuggingFaceTB/smollm3-configs](https://huggingface.co/datasets/HuggingFaceTB/smollm3-configs)

| Stage | Tokens | Context | Mix |
|---|---|---|---|
| 1 — Base | **8T** | 4k | Web: FineWeb-Edu, DCLM, FineWeb2, FineWeb2-HQ · Code: The Stack v2, StarCoder2 PRs, Jupyter/Kaggle notebooks, GitHub issues, StackExchange · Math: FineMath3+, InfiWebMath3+ |
| 2 — Stable | **2T** | 4k | Adds Stack-Edu; higher-quality math+code (FineMath4+, InfiWebMath4+, MegaMath). Code 12% → 15% |
| 3 — Decay | **1.1T** | 4k | Further upsamples math+code (code → 24%); adds OpenMathReasoning |
| 4 — Long ctx | **+100B** (2×50B) | 4k→32k (RoPE θ=1.5M) → 32k→64k (θ=5M) | Upsampled math/code/reasoning; **YaRN** at inference → 128k |

> **The most useful negative result in open LLM training:** *"we found that upsampling specific long context data such as code repositories, books, and long web pages … **didn't further boost performance on RULER and HELMET**. Using NoPE and training on the decay mixture with longer sequences and increased RoPE theta values was sufficient."* They hypothesise the baseline mixture already contains ~10% naturally-long documents. **You may not need a dedicated long-context corpus at all.**
>
> ⚠️ **The SmolLM3 pretraining corpus itself was never released** — only the configs and blueprint. The recipe is open; the mix is not.

### 4.3 nanochat (Karpathy)

- Original: pretrain on ~100B tokens of **FineWeb-Edu** → midtrain on **SmolTalk** + MMLU multiple-choice + GSM8K → SFT. ([repo](https://github.com/karpathy/nanochat))
- **March 2026: switched the pretraining corpus to NVIDIA ClimbMix**, reporting that "Olmo, FineWeb, and DCLM led to regressions, while ClimbMix worked well out of the box." With FP8, nanochat now hits GPT-2 capability in **~2 h on one 8×H100 node**. ([karpathy/climbmix-400b-shuffle](https://huggingface.co/datasets/karpathy/climbmix-400b-shuffle) · [discussion #696](https://github.com/karpathy/nanochat/discussions/696))
- ⚠️ **ClimbMix is CC-BY-NC-4.0.** Fine for nanochat-style research; not for a commercial model.

### 5.4b How to audit provenance **without downloading anything**

This is the technique that caught SWE-smith-trajectories, and it costs one HTTP call per dataset. The HF **datasets-server preview API** returns the schema plus the first ~100 rows:

```bash
# 1. List configs/splits
curl -s "https://datasets-server.huggingface.co/splits?dataset=ORG%2FNAME" | jq -c '.splits'

# 2. Pull the schema + first rows, and read any provenance column
curl -s "https://datasets-server.huggingface.co/first-rows?dataset=ORG%2FNAME&config=default&split=train" \
  | jq -r '[.features[].name] | join(", ")'                    # what columns exist?
  # then read values of any column matching: model|generator|teacher|llm|source|response_model

# 3. Grep the raw preview for provider strings as a backstop
curl -s "https://datasets-server.huggingface.co/first-rows?dataset=ORG%2FNAME&config=default&split=train" \
  | grep -oic -e claude -e sonnet -e anthropic -e 'gpt-4' -e gemini
```

Interpreting the result:
- **A provenance column with a model id is definitive** (e.g. `model = claude-3-7-sonnet-20250219`, `model_name = swe-agent-llama-70b`).
- **No provenance column ⇒ unauditable, not "clean."** `SWE-Gym/OpenHands-SFT-Trajectories` ships only `messages`; NVIDIA's `SWE-Zero`/`SWE-Hero` ship no model field. Treat these as UNKNOWN and prefer datasets that document their teachers.
- **String markers** are a weak backstop only — models rarely self-identify inside agent trajectories, and `\n\nHuman:` / `\n\nAssistant:` produce heavy false positives because many datasets copy the Anthropic HH chat format without containing Anthropic output.
- **Check transitively.** A dataset can be clean itself and still ingest a contaminated upstream — `QuixiAI/dolphin-distill` publishes its component table, which is how the 142,585 SWE-smith-trajectories rows are visible.

### 8.2 The exact method — `decon`'s real parameters

⚠️ **Correction to the widely-repeated "8-gram" description.** That is the **Tulu 3 / open-instruct *post-training*** approach (word-level 8-gram overlap). Ai2's **pretraining/midtraining** decontaminator, `decon`, works differently — verified from [`config/default.yaml`](https://raw.githubusercontent.com/allenai/decon/main/config/default.yaml):

| Parameter | Default | Meaning |
|---|---|---|
| `tokenizer_str` | **`cl100k`** | **Token**-level, not word-level |
| `ngram_size` | **5** | Size of indexed n-grams scanned for question matches |
| `sample_every_m_tokens` | **10** | Sampling stride through the training doc |
| `question_max_consecutive_misses` | 11 | A mismatched token can poison n-gram spans |
| **`contamination_score_threshold`** | **0.80** | The main combined score |
| `perfect_match_decay_start` / `_end` | 20 / 50 | Require a *perfect* match for short items (cum. length ≤20); use the threshold at ≥50; linear interpolation between |
| `short_answer_token_threshold` / `_window_length` | 3 / 50 | Answers ≤3 tokens use exact matching |
| `answer_ngram_size` / `min_long_answer_window` | 3 / 100 | Long answers use n-gram **idf overlap ratios** |
| `passage_ngram_size` / `min_passage_distance` / `passage_max_consecutive_misses` | 4 / 100 / 2 | Passage-match expansion |
| `eval_dedup` / `eval_min_token_length` / `eval_min_unique_word_count` | true / 20 / 4 | Reference-set preprocessing |

**Ai2's own reproduction configs reveal that they tuned the threshold per data type** ([`doc/repro/`](https://github.com/allenai/decon/tree/main/doc/repro)):

| OLMo 3 midtraining run | `contamination_score_threshold` | Notable deltas vs default |
|---|---|---|
| [`olmo-web.yaml`](https://raw.githubusercontent.com/allenai/decon/main/doc/repro/olmo-web.yaml) (web data) | **0.88** | decay 25/50; short-answer threshold 1, window 20; answer n-gram 2 |
| [`olmo-synth.yaml`](https://raw.githubusercontent.com/allenai/decon/main/doc/repro/olmo-synth.yaml) (synthetic data) | **0.78** | decay **5/26** (much more aggressive on short facts); short-answer threshold 1 |

> Ai2's own note in `olmo-web.yaml`: the repro config *"produces approximately the same outcomes as the decontamination run against web data for olmo midtraining… 90% overlap for original contamination with 25% additional contamination discoveries"* — and *"the standard default configuration results in meaningfully higher accuracy."* **Use the defaults, not the repro configs**, unless you're reproducing OLMo 3 exactly.

**The recipe to implement:**
1. Run `decon detect --purify` with defaults (cl100k, 5-gram, threshold 0.80).
2. **Decontaminate at midtraining and long-context above all.** OLMo 3's rationale: *"memorization happens most strongly near the end of training, so decontaminating at the midtraining stage (and for long-context extensions) is most effective."*
3. For **post-training** data, additionally run the open-instruct **8-gram word-level** overlap script ([allenai/open-instruct](https://github.com/allenai/open-instruct), [arXiv:2411.15124](https://arxiv.org/abs/2411.15124)).
4. Consider FineMath's stricter variant for math corpora: **13-gram + LCS overlap ratio ≥0.6** ([finemath_contamination_report](https://huggingface.co/datasets/HuggingFaceTB/finemath_contamination_report) — it removed 5,326 pages).
5. Preserve **canary GUIDs** (BIG-bench / lm-eval-harness convention) in anything you release.
6. **Accept that n-gram decon is necessary but not sufficient** — §8.4.

### 8.4 Known contamination issues

- **Skywork-Reward v0.1 → v0.2**: v0.1 had a decontamination defect; always use [v0.2](https://huggingface.co/datasets/Skywork/Skywork-Reward-Preference-80K-v0.2).
- **"Soft contamination"** ([arXiv:2602.12413](https://arxiv.org/html/2602.12413v1), 2026): semantic (non-lexical) overlap is widespread and n-gram decon does **not** catch it.
- **LiveCodeBench** uses **date-windowing** (only problems published after a model's cutoff) as a structural defence. **SWE-rebench** does the same via continuous PR refresh.
- **Reward hacking is a separate data hazard.** NVIDIA removed "git hacking" trajectories from `Open-SWE-Traces` in Aug 2026 following [arXiv:2609.06780](https://arxiv.org/abs/2609.06780), cutting 207k → 151k trajectories. Budget for this kind of filtering, not just contamination.
- A public probe exists for OLMo 3: [nthngdy/mmlu_olmo3_contamination](https://huggingface.co/datasets/nthngdy/mmlu_olmo3_contamination).
- **UNVERIFIED:** whether nanochat performs any decontamination, and whether ClimbMix ships decontaminated. Assume neither until confirmed.

**Planning rules:**
- **zstd-JSONL: ~0.75–1.9 bytes/token** — the most space-efficient open format, and what Ai2 ships.
- **Parquet (gzip/snappy) text: ~2.7–4.5 bytes/token.**
- **Pre-tokenized uint32 ID arrays: ~5 bytes/token — *worse* than compressed text.** Detokenize or re-pack ClimbMix before storing.
- **After you tokenize and pack for training:** 2 bytes/token (vocab ≤65k, uint16) or 4 bytes/token (uint32). 10B packed tokens ≈ **20–40 GB**.

### 9.2 Cost per scale

| Scale | Raw download | Packed training bins (uint32) | Fits a 2 TB T7? |
|---|---|---|---|
| **10B tokens** | **~10–45 GB** | ~40 GB | ✅ Trivially |
| **100B tokens** | **~75–270 GB** (the HF 100B blend is exactly **267.9 GB**) | ~400 GB | ✅ Comfortably |
| **1T tokens** | **~0.75–3.0 TB** | ~4 TB | ⚠️ **Only if you pick zstd sources.** Dolma-3-style ≈ 750 GB/T |
| **10T tokens** | **~7.5–30 TB** | ~40 TB | ❌ NAS / S3 / streaming |

> **The decisive trick for a 2 TB drive:** the *same 1T tokens* costs **750 GB from Ai2's zstd-JSONL** vs **4.5 TB from FineWeb-Edu's gzip-parquet** — a **6× difference driven purely by which publisher you pull from.** Also use `huggingface-cli download --include` to pull single configs, and `load_dataset(..., streaming=True)` above ~1T.
